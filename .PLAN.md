  * ## Ticket: 00_util.js: datetimes, durations, list grammar, FNV-1a, CSV {#3}

        status: done
        created: 2026-09-22 12:48:09 UTC
        updated: 2026-09-22 12:53:06 UTC

    Implement in `src/00_util.js` as plain functions or a `Util` namespace
    object. Unit tests in `test/util.test.js`.

    Datetimes (DESIGN 3.3, 4): represent instants as integer minutes since
    1970-01-01T00:00 with the wall clock treated as UTC. `parseDateTime(text)`
    accepts `YYYY-MM-DDTHH:MM`, `YYYY-MM-DD HH:MM`, `YYYY-MM-DD` (00:00);
    returns null on anything else, including out-of-range fields.
    `formatDateTime(min)` returns canonical `YYYY-MM-DDTHH:MM`.
    `parseDate(text)` for holidays, `YYYY-MM-DD` only. Helpers: day index of
    an instant, weekday, start of day.

    Durations: `parseDuration(text)` for chained `Nw Nd Nh Nm` tokens like
    `1w`, `3d`, `12h`, `1d12h`, `90m`; returns minutes or null. `parsePeriod`
    accepts only `w` and `d`. `formatDuration(min)` produces the shortest
    chained form.

    Lists (3.3): `splitList(text)` splits on `,` or `;`, trims, drops empties.
    `parseAssignments(text)` returns items `{ name, op, value }` with `op` in
    `=`, `+=`, `-=`, or none; value is the raw string; names must not contain
    `=` or `+`. Returns an error string for malformed items.

    `fnv1a32(string)` returning an unsigned 32-bit integer.

    CSV: `parseCsv(text)` and `formatCsv(rows)` handling quotes, embedded
    commas, quotes and newlines, CRLF input. Used by the Node adapter and
    fixtures only, but lives here so it has no imports.

    `Grid` from `{ period, anchor }`: `floor(t)` last boundary <= t,
    `next(t)` first boundary strictly > t, `ceil(t)` first boundary >= t,
    `boundariesBetween(a, b)`. Integer arithmetic on minutes; anchor may be

    summed per calendar day, days skipped when `skip_weekends` and the day is

    holidays set. Exact for partial days. Test: a Mon 09:00 to Mon 09:00 week

    explicit end, else next grid boundary strictly after start, truncated by
    the next kept shift start and by the next `set` row that changes period
    or anchor. `scoredEnd(shift, nextShiftStart, grid)` per DESIGN 3.4:
    explicit end, else next shift start, else next grid boundary.

  * ## Ticket: 40_scheduler.js: advance, prune, slots, pre-credit, sweep, selection {#7}

        status: done
        created: 2026-09-22 12:48:09 UTC
        updated: 2026-09-22 13:27:27 UTC

    Implement in `src/40_scheduler.js`. Tests in `test/scheduler.test.js`.
    This is DESIGN section 5 end to end for one or many rotations.

    API:
    - `advance(ledger, holidays, now)` returns the snapshot instant `S` per
      DESIGN 5.2 (shift containing now, else grid floor of now, raised to
      anchor, first roster row, existing snapshot).
    - `regenerate({ rotations: [{ name, rows, snapshotAt }], holidays,
      links: [] })` returns `{ rotations: [{ name, rows }], errors, status }`
      where `status` has per-rotation roster scores at `S` and projected at
      horizon end, plus warnings. Pure: no clock, no randomness.

    Steps inside regenerate, per DESIGN 5.3 to 5.8: drop `error` rows; prune
    unpinned shifts with start > S; sort; compute claims and uncovered spans
    from `regenStart` (claim end of the shift at S, else S) to `horizonEnd`
    (grid ceil of S + horizon); split spans at grid boundaries into slots;
    pre-credit pinned shifts in `(S, S + precredit*period)`; sweep all
    rotations' items merged by start with ties by rotation order then type
    order; replay begins at the previous snapshot with `set` rows from the
    top and clipped intervals; record the new snapshot when passing S;
    selection per DESIGN 5.7 with symmetric min_distance, tolerance band,
    `order` and `shuffle` tiebreaks, gradual relaxation of min_distance,
    nobody plus `error` row when unassignable, relaxation note on generated
    shifts. Output rows sorted, old snapshot replaced, no explicit end on the
    last row.

    Validation errors from 10_model and stateful errors from 30_state make
    regenerate return the input rows unchanged plus `error` rows placed at
    the offending row's start with the message, and skip everything else.

    Tests must include: idempotence (regenerate twice gives identical rows);
    determinism of shuffle across runs and its change with seed; fill shift
    after a pinned substitution; pin inside and outside the precredit window;
    exclusion honoured, min_distance relaxed with note; team diff with
    baselines; period change via `set` realigning the grid; unassignable
    slot; advance placement in each of the five cases of DESIGN 5.2.

    * ## Comments {#7:comments}

      * Sweep is one loop over items merged by (start, rotation index, order): row items use ROW_TYPES order; script items are snapshot (2), tail credit of an interval spanning S (2.5), precredit (8.5, after roster rows and before the shift at S), slots and kept-shift credits (9). Pre-credit runs when the sweep reaches S rather than before the sweep, because precredit=auto needs the roster size at S and a team row dated at S sorts after the snapshot. Scored intervals of kept and generated shifts use the final shift list (kept plus slots) for the next-shift rule. Exclude rows older than the previous snapshot are clipped using the end resolved from later include rows; a clipped exclude for a member no longer on the roster is skipped silently.   * ## Ticket: Task: Setup and new-rotation bootstrap in Apps Script and core {#41}

        status: open
        created: 2026-09-23 02:47:35 UTC
        updated: 2026-09-23 09:22:32 UTC

    No dialogs. Three menu items, all in 90_gas.js with the row logic in the core.

    **Set up.** Idempotent `setup()`: create missing `#Holidays`, `#Links`,
    `#Status`, `#All shifts` with headers; if no rotation exists create `On-Call`
    from the rotation template; on every tab apply Roboto Mono to the whole
    sheet, plain text number format on whole ledger columns (`A:G`) so new rows
    inherit like the UI does on select-all, bold and frozen header row, column
    widths per ledger column, delete empty columns beyond `note`; header cell
    notes (setNote) explaining each column; tab colours only on `#` tabs, one
    colour for generated tabs (#Status, #All shifts, previews) and another for
    editable ones (#Holidays, #Links). Never rewrites existing data. Runner keeps
    applying plain text to ranges it writes. Preview tabs are created at the
    index right after their rotation (insertSheet(name, index)) and never moved.

    **Template.** Fills the active tab from its type detected by name. Rotation
    tab (not starting with `#`): must be empty, otherwise toast and refuse;
    writes header, a `set` row listing every key explicitly at its default
    including bare `anchor`, dated the most recent Monday 09:00, and a `team`
    row with sample names. `#Holidays` and `#Links`: header only plus header
    notes. Generated tabs: toast, nothing to do.

    **Fill Shifts Grid.** Requires a selection of more than one row in a rotation
    tab; otherwise toast. Fills in `start` (and sets `type` to `shift` where it is
    unset) so that after the command the selected region has every `start`
    filled. `end` and `duration` are never written; a dated row without them is
    treated as spanning to the next grid boundary for gap detection. All other
    columns of existing rows travel with their rows untouched. Every row without
    `start` must be entirely blank or have only `type` = `shift`; any other
    undated row stops the command with a toast naming it, since it can neither be
    placed on the timeline nor safely wiped.
    Algorithm over the selected rows:
    1. `n_pre` = empty rows before the first dated row; `n_post` = empty rows
       after the last dated row.
    2. Between them: drop empty rows, sort by start (3.6 type order for ties),
       keep non-shift rows in place in the order, treat dated shift rows without
       end or duration as claiming to the next grid boundary (truncated by the
       next row), insert a `shift` row with empty `what` at every uncovered grid
       boundary and at every gap start, exactly like generation but without
       assignment.
    3. Generate `n_pre` rows at the `n_pre` grid boundaries before the first
       dated row's start, and `n_post` rows at the boundaries after the last
       row's claim end.
    4. Write the result over the selected region (it grows by the number of
       inserted gap rows) and set the active range to the affected rows.
    This covers backfill (empty rows above), extension (empty rows below) and
    gap filling (dated rows with holes) with one command. Core: pure
    `gridRows(rows, nPre, nPost)` over row objects, using the ledger's settings
    timeline and the claim helpers; plus `templateRows(firstStart)`; unit tests
    for both. INSTALL
    rewritten around Set up, Template and Fill Shifts Grid; the manual template
    remains as an appendix and notes that formatting inheritance for new rows is
    to be confirmed on a live sheet.

    Documentation: the rule for rows without `end` or `duration` (they end at the
    earlier of the next shift start and the next grid boundary, so multi-period
    history rows need `duration` or `end`) gets its own short paragraph in README
    under the `shift` row type and in INSTALL under history import.
