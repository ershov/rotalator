  * ## Ticket: 00_util.js: datetimes, durations, list grammar, FNV-1a, CSV {#3}

        status: done
        created: 2026-09-22 12:48:09 UTC
        updated: 2026-09-22 12:53:06 UTC

    Implement in `src/00_util.js` as plain functions or a `Util` namespace
    object. Unit tests in `test/util.test.js`.

    Datetimes (DESIGN 3.3, 4): represent instants as integer minutes since
    1970-01-01T00:00 with the wall clock treated as UTC. `parseDateTime(text)`
    accepts `YYYY-MM-DDTHH:MM`, `YYYY-MM-DD HH:MM`, `YYYY-MM-DD` (00:00);
    returns null on anything else, including out-of-range fields.
    `formatDateTime(min)` returns canonical `YYYY-MM-DDTHH:MM`.
    `parseDate(text)` for holidays, `YYYY-MM-DD` only. Helpers: day index of
    an instant, weekday, start of day.

    Durations: `parseDuration(text)` for chained `Nw Nd Nh Nm` tokens like
    `1w`, `3d`, `12h`, `1d12h`, `90m`; returns minutes or null. `parsePeriod`
    accepts only `w` and `d`. `formatDuration(min)` produces the shortest
    chained form.

    Lists (3.3): `splitList(text)` splits on `,` or `;`, trims, drops empties.
    `parseAssignments(text)` returns items `{ name, op, value }` with `op` in
    `=`, `+=`, `-=`, or none; value is the raw string; names must not contain
    `=` or `+`. Returns an error string for malformed items.

    `fnv1a32(string)` returning an unsigned 32-bit integer.

    CSV: `parseCsv(text)` and `formatCsv(rows)` handling quotes, embedded
    commas, quotes and newlines, CRLF input. Used by the Node adapter and
    fixtures only, but lives here so it has no imports.

    * ## Comments {#3:comments}

      * Plain global functions, no Util namespace. parseDate returns a day index (days since 1970-01-01) to match dayIndex(); weekday() uses JS convention 0=Sunday. Duration tokens must be in strictly descending unit order (12h1d, 1d1d rejected); parsePeriod also rejects 0. parseAssignments rejects empty name/value and values containing = or +; a bare item containing + is an error. fnv1a32 hashes the UTF-8 bytes. parseCsv skips blank lines; formatCsv quotes on , " CR LF only. Tests deep-compare through structuredClone because vm-context arrays have foreign prototypes. {#3:comment:18}

      * Review fixes: reject years < 100 (Date.UTC two-digit-year mapping); parseCsv only skips lines with no characters and formatCsv writes a lone empty field as "" so it round-trips; fnv1a32 iterates code points so lone surrogates stay non-negative; build.sh iterates the glob directly; parseDate/formatDate renamed parseDay/formatDay since they use day indexes. {#3:comment:19}

  * ## Ticket: 20_calendar.js: grid, claims, units {#5}

        status: done
        created: 2026-09-22 12:48:09 UTC
        updated: 2026-09-22 13:03:32 UTC

    Implement in `src/20_calendar.js`. Tests in `test/calendar.test.js`.

    `Grid` from `{ period, anchor }`: `floor(t)` last boundary <= t,
    `next(t)` first boundary strictly > t, `ceil(t)` first boundary >= t,
    `boundariesBetween(a, b)`. Integer arithmetic on minutes; anchor may be
    before or after t.

    `units(a, b, options)` per DESIGN 4: fractional days covered by `[a, b)`,
    summed per calendar day, days skipped when `skip_weekends` and the day is
    Saturday or Sunday, or `skip_holidays` and the day index is in the
    holidays set. Exact for partial days. Test: a Mon 09:00 to Mon 09:00 week
    is 7, or 5 with skip_weekends; a 12h span straddling midnight into a
    skipped day credits 0.5 minus the skipped part.

    `claimEnd(shift, nextShiftStart, gridAt, gridChanges)` per DESIGN 5.4:
    explicit end, else next grid boundary strictly after start, truncated by
    the next kept shift start and by the next `set` row that changes period
    or anchor. `scoredEnd(shift, nextShiftStart, grid)` per DESIGN 3.4:
    explicit end, else next shift start, else next grid boundary.

    * ## Comments {#5:comments}

      * Grid takes a { period, anchor } object; boundariesBetween(a, b) is exclusive on both ends. units options use the setting key names (skip_weekends, skip_holidays) plus holidays as a Set or array of day indexes; sums integer minutes then divides once. claimEnd truncates explicit ends too by next shift and grid change; gridAt may be a Grid or a function t -> Grid. Loader now publishes top-level classes onto the vm global so tests can reach them. {#5:comment:21}

    `Settings`: defaults from DESIGN 3.5, `apply(setRow)` with the rule that

    `precredit=auto` resolved at use time from roster size. Provide
    `settingsAt(setRows, t)` that replays all `set` rows with start <= t.
    Report which `set` rows change the grid (period or anchor).

    `Roster`: ordered members with `score`, plus exclusions (list of
    `[from, to)` per member, `to` may be open). Operations, each taking the
    instant and returning validation errors for stateful rules:
    - `team(list)`: diff per DESIGN 3.4; leavers removed; joiners appended in
      list order with baseline; existing members reordered to list order;
      `=n`, `+=n`, `-=n` applied after joining.
    - `join(who, baselineArg)`, `leave(who)`, `score(list)`,
      `exclude(who, from, to)`, `include(who)` closing the open exclusion.
    - `baseline(kind)` computed over all roster members' current scores:
      median (mean of the two middle values for even counts), mean, min, max.
      Empty roster gives 0.
    - `credit(who, units)`; `isExcluded(who, a, b)` any overlap.
    - `snapshotArg()` producing `alice=12.50, bob=11.00` in roster order and
      `fromSnapshotArg(text)` restoring it.
    - Clipping helper for intervals extending past the snapshot instant.

    * ## Comments {#6:comments}

      * Settings.apply reports a grid change only when the period or anchor value actually differs; a set row repeating the same period does not move the anchor. SettingsTimeline caches settings after each set row; settingsAt/gridChanges wrap it. Roster.team joins new members sequentially in list order (each baseline sees earlier joiners), reorders to list order, then applies =, += and -= (= on an existing member accepts a baseline keyword too). include closes every exclusion of the member active at that instant and errors when there is none. credit to a name not on the roster is ignored. Scores format via formatScore, which maps -0.00 to 0.00 so snapshots round-trip. {#6:comment:23}

  * ## Ticket: 40_scheduler.js: advance, prune, slots, pre-credit, sweep, selection {#7}

        status: done
        created: 2026-09-22 12:48:09 UTC
        updated: 2026-09-22 13:27:27 UTC

    Implement in `src/40_scheduler.js`. Tests in `test/scheduler.test.js`.
    This is DESIGN section 5 end to end for one or many rotations.

    API:
    - `advance(ledger, holidays, now)` returns the snapshot instant `S` per
      DESIGN 5.2 (shift containing now, else grid floor of now, raised to
      anchor, first roster row, existing snapshot).
    - `regenerate({ rotations: [{ name, rows, snapshotAt }], holidays,
      links: [] })` returns `{ rotations: [{ name, rows }], errors, status }`
      where `status` has per-rotation roster scores at `S` and projected at
      horizon end, plus warnings. Pure: no clock, no randomness.

    Steps inside regenerate, per DESIGN 5.3 to 5.8: drop `error` rows; prune
    unpinned shifts with start > S; sort; compute claims and uncovered spans
    from `regenStart` (claim end of the shift at S, else S) to `horizonEnd`
    (grid ceil of S + horizon); split spans at grid boundaries into slots;
    pre-credit pinned shifts in `(S, S + precredit*period)`; sweep all
    rotations' items merged by start with ties by rotation order then type
    order; replay begins at the previous snapshot with `set` rows from the
    top and clipped intervals; record the new snapshot when passing S;
    selection per DESIGN 5.7 with symmetric min_distance, tolerance band,
    `order` and `shuffle` tiebreaks, gradual relaxation of min_distance,
    nobody plus `error` row when unassignable, relaxation note on generated
    shifts. Output rows sorted, old snapshot replaced, no explicit end on the
    last row.

    Validation errors from 10_model and stateful errors from 30_state make
    regenerate return the input rows unchanged plus `error` rows placed at
    the offending row's start with the message, and skip everything else.

    Tests must include: idempotence (regenerate twice gives identical rows);
    determinism of shuffle across runs and its change with seed; fill shift
    after a pinned substitution; pin inside and outside the precredit window;
    exclusion honoured, min_distance relaxed with note; team diff with
    baselines; period change via `set` realigning the grid; unassignable
    slot; advance placement in each of the five cases of DESIGN 5.2.

    * ## Comments {#7:comments}

      * Sweep is one loop over items merged by (start, rotation index, order): row items use ROW_TYPES order; script items are snapshot (2), tail credit of an interval spanning S (2.5), precredit (8.5, after roster rows and before the shift at S), slots and kept-shift credits (9). Pre-credit runs when the sweep reaches S rather than before the sweep, because precredit=auto needs the roster size at S and a team row dated at S sorts after the snapshot. Scored intervals of kept and generated shifts use the final shift list (kept plus slots) for the next-shift rule. Exclude rows older than the previous snapshot are clipped using the end resolved from later include rows; a clipped exclude for a member no longer on the roster is skipped silently. Shuffle hash key is seed|rotation|YYYY-MM-DDTHH:MM|member. Unassignable slots are returned in errors and status.warnings but do not block regeneration; stateful roster errors do, and further items of that rotation are skipped after the first. regenerate raises S to the existing snapshot and the first row; a missing snapshotAt falls back to advance(rows, holidays, null). Links argument accepted and ignored. {#7:comment:24}

      * Review fixes: precredit skips pins whose assignee is not on the roster at S, so they are credited when reached (test added); slot entries use their own end as scored end, so a pin beyond horizonEnd no longer stretches the last generated shift (test added); the tail credit of a shift spanning S has shift order, so team/join rows at S see the same scores as the snapshot; regenerate takes holidays as day indexes only (adapter converts and reports bad cells); advance(rows, now) no longer takes holidays; DESIGN 5.5 reworded to say pins are credited when the sweep reaches S; removed unused settingsAt, gridChanges, Grid.isBoundary, Grid.boundariesBetween, isWeekend, startOfDay and the unreachable else in Roster.score. {#7:comment:25}
